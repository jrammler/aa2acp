# Project conventions

## Repository scope

This repository contains only the Raspberry Pi C++ bridge. Do not add external
head-unit software, emulators, ESP32 experiments, or unrelated test assets.

## Building and testing

Two supported build paths produce identical results; dependencies are pinned
in `deps.lock` and patches live in `patches/aasdk/`.

- Plain Linux (also what CI does): install the apt build deps (see README),
  run `./scripts/build-deps.sh` once, then configure with
  `-DCMAKE_PREFIX_PATH="$PWD/.deps/install"`.
- Nix: run commands through the dev shell (`nix develop --command ...`).

Before committing C++ changes, format, build, and test:

```bash
find include src tests -type f \( -name "*.cpp" -o -name "*.hpp" \) \
  -print0 | xargs clang-format -i
cmake -S . -B build && cmake --build build -j2
ctest --test-dir build --output-on-failure
git diff --check
```

clang-format **21** is canonical; CI enforces it via a pip pin, and the Nix
dev shell provides it through `llvmPackages_21.clang-tools`.

Keep commits focused; commit completed work regularly. Pushing to `main`
triggers CI (build + tests + format check on ubuntu-26.04-arm in a
debian:trixie container). Never link Abseil internal targets unconditionally;
see the comment at the `ABSL_LOG_LINK` logic in CMakeLists.txt.

## Releases

The package version is derived automatically: base version lives in the
`VERSION` file; CMake refines it via `git describe` (exact tag on release
commits), and Nix builds append the short revision. To cut a release: bump
`VERSION`, commit, then tag that commit (`git tag v0.1.1 && git push origin
v0.1.1`); the release workflow fails if the tag does not match `VERSION`. The `release.yml` workflow calls the reusable `build.yml`
(Release build type), packages the deb with CPack, and publishes both
`aa2acp.deb` and the raw binary on a GitHub Release. Release notes are
auto-generated by GitHub; consider editing them afterwards.

## Documentation map

Keep each topic in exactly one place: README.md (install/usage/dev/releases),
TODO.md (roadmap), TESTING.md (runbook + diagnostics). When changing runtime
behavior that affects docs (paths, services, hotspot behavior), update the
corresponding doc in the same commit.
